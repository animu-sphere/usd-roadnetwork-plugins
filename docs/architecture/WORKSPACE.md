# Workspace contract

- **Status:** Binding for §1–§4 and §6 (2026-11-22, SCF-02); §5 stays
  proposed until its ADRs are accepted. The workspace root and the
  `roadnetwork-opendrive` bundle are generated by `ost`; the template and
  generator versions are recorded in each `openstrata.scaffold.yaml`.
  `roadnetwork-core` and `roadnetwork-usd` are hand-written after the
  `usd-3dgs-plugins` libraries and declared as workspace members in
  `openstrata.toml`.

This is the structural contract for `usd-roadnetwork-plugins`. It fixes
component identities and responsibilities, dependency directions, root
responsibilities, and the authored stage contract. A structural change that
contradicts this document must change this document first.

What each component does today is in its README (linked below) and in the
[capability matrix](../reference/CAPABILITY_MATRIX.md); this page does not
track implementation state.

## 1. Components

| Identity | Kind | Owns | Must not take on | Documentation |
| --- | --- | --- | --- | --- |
| `roadnetwork-opendrive` | OpenStrata plugin bundle (`usd-fileformat`) | `.xodr` detection, XML reading, version recognition, semantic decoding into `RoadNetworkData`, and `ODR-` diagnostics | Authoring individual prims; geometry math | [README](../../plugins/roadnetwork-opendrive/README.md) |
| `roadnetwork-lanelet2` | plugin bundle | Lanelet2 `.osm` (Phase 4 candidate) | as above | — |
| `roadnetwork-sumo` | plugin bundle | SUMO `.net.xml` (Phase 4 candidate) | as above | — |
| `roadnetwork-core` | plain CMake/OpenStrata static library | The value-based `RoadNetworkData`, ID and connectivity validation, geometry evaluation and sampling, and `RN-` diagnostics | Any OpenUSD type; any format parser | [README](../../libs/roadnetwork-core/README.md) |
| `roadnetwork-usd` | plain CMake/OpenStrata static library | Authoring `RoadNetworkData` into the stage contract (§5): Sdf specs, properties, relationships, provenance | XML parsing; geometry math of its own (it uses `roadnetwork-core`) | [README](../../libs/roadnetwork-usd/README.md) |
| Integrating runtime | other repository | Routing graphs, spatial search, collision, traffic, loading strategy | Re-interpreting a supported source format | [API boundary](API_BOUNDARY.md) |

`roadnetwork-core` is not a plugin: it has no `plugInfo.json`, performs no
plugin registration, and exposes no OpenUSD types in its public API.

## 2. Dependency directions

Allowed:

```text
roadnetwork-opendrive -> roadnetwork-core
roadnetwork-opendrive -> roadnetwork-usd
roadnetwork-opendrive -> <XML parser> (private, pinned; selected by FMT-01)
roadnetwork-usd       -> roadnetwork-core
roadnetwork-usd       -> OpenUSD
```

Forbidden:

```text
roadnetwork-core -> any plugin bundle
roadnetwork-core -> OpenUSD
roadnetwork-core -> any format parser
roadnetwork-usd  -> any plugin bundle
roadnetwork-usd  -> any format parser
<bundle>         -> another format bundle
any dependency cycle
```

Libraries declare an OpenStrata descriptor (`openstrata.library.yaml`) so
that bundles can name them in `requires.libraries` and `ost plugin
build/test/package` can resolve them. `ost plugin test --workspace
--graph-only` checks these edges without a build.

| Library id | CMake package | CMake target | Requires |
| --- | --- | --- | --- |
| `roadnetwork-core` | `roadnetworkCore` | `openstrata::roadnetworkCore` | — |
| `roadnetwork-usd` | `roadnetworkUsd` | `openstrata::roadnetworkUsd` | `roadnetwork-core`, OpenUSD (`arch tf vt sdf`) |

As in `usd-3dgs-plugins`, tests and fixtures live inside the bundle or
library they exercise; the root `tests/` holds only cross-format and
aggregate package tests. Bundle fixtures are declared in the bundle manifest
so package tests can find them. Build state (`.strata/`, `build/`, `lib/`,
`dist/`, `strata.lock`) and CMake or IDE products are generated and ignored
by the root `.gitignore`, at any depth.

## 5. Authored stage contract

*Proposed; settled by [ADR 0002](../adr/0002-usd-schema-strategy.md)
(prim types and properties), [ADR 0003](../adr/0003-crs-axes-units.md)
(axes, units, origin), and [ADR 0005](../adr/0005-prim-path-and-id-stability.md)
(paths and relationships). The proposed tree is
[ADR 0005 §3](../adr/0005-prim-path-and-id-stability.md#3-hierarchy); it is
not copied here, so that the ADR stays the single place it is reviewed.*

The top level is fixed:

```text
/Asset                Xform, defaultPrim; provenance
  /Network            semantic root, always authored
  /Visualization      derived geometry, optional
```

Invariants every bundle must satisfy once the contract is accepted:

- one shared writer authors the stage; bundles never author prims directly;
- `defaultPrim` is `Asset`;
- paths derive deterministically from source IDs (ADR 0005), and every
  relationship target is inside `/Asset`;
- `/Network` is complete without `/Visualization`; visualization is derived
  data and never the only carrier of semantics;
- each `upAxis` and `metersPerUnit` value is documented in the format's
  mapping as either a source fact or an importer default (ADR 0003);
- import provenance (source format, version, counts, warnings) is recorded
  on `/Asset`, and no environment-dependent value such as an absolute path
  is authored.

## 6. Packaging

Each bundle packages independently. A release requires that a plugin is
discovered and opens a fixture **from the installed package**, not only from
the source tree (see the [release gate](../releases/README.md#release-gate)).
